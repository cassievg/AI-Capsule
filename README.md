# Installation and Running the Project

## Frontend

To install the dependencies for the frontend of the project, navigate to the frontend folder and run `npm install`.
```
cd frontend
npm install
```

Then run the frontend using `npm run build`.

## Backend

To install the dependencies for the backend of the project, navigate to the backend folder and run `npm install`.
```
cd backend
npm install
```

In the same terminal, run `npm start` to start the server.

Note that both the frontend and backend must be running in parallel for the app to work.

# Database Creation

Database was created using sqlite3 v6.0.1, an ephemeral storage. The complete DB initialization can be viewed in `backend/db.js`.
There is only one table in the DB named 'capsules'.

Below lists the fields of the 'capsules' table.
- `id`: The unique ID that acts as the identifier for each capsule. Automatically generated by the backend incrementally.
- `user_id`: The GitHub ID of users who visit and use this app. Automatically obtained by the GitHub OAuth.
- `project_name`: The name of the project.
- `prompt_title`: The title of the prompt.
- `prompt_version`: The version of the prompt.
- `prompt_text`: The body text of the prompt.
- `response_summary`: The summary of the AI's response for the prompt.
- `category`: The task type of the project.
- `usefulness`: Student's rating of the usefulness.
- `reviewed`: Whether the response has been checked.
- `improved`: Whether the output has been improved.
- `screenshot_url`: A URL link of a screenshot evidence.
- `notes`: Additional notes if any.
- `created_at`: Time of creation of the capsule.

# API

Complete API routes can be viewed in `backend/routes`. There are two API routing files, `auth.js` and `capsules.js`.

`auth.js`:
- `GET /github`: Leads to the GitHub OAuth.
- `GET /github/callback`: Callback for the authentication. User identification and token handling are also done here.

`capsules.js`:
- `GET /capsules`: Get all capsules.
- `GET /capsules/:id`: Get capsule by ID.
- `POST /capsules`: Create a new capsule.
- `PUT /capsules/:id`: Update a capsule.
- `DELETE /capsules/:id`: Delete a capsule.

Note that the ownership of capsules are maintained and identified by the user ID field of the database. This ensures that these capsule API routes will only affect the capsules of the logged in user, while capsules that belong to other users will not be affected not displayed on the dashboard.

# Frontend-Backend Communication

Express is used for communication between the frontend and the backend. This is done by configuring the baseURL for the axios to the deployed [backend](https://ai-capsule-backend.onrender.com/api/health)

# Authentication

Authentication is handled using GitHub OAuth, where the user's GitHub profile is used in the app. The full process can be seen in the `GET /github` and `GET /github/callback` routes in `routes/auth.js`. Here, successful GitHub OAuth authentication will exchange the authorization code for the GitHub access token, and the user's GitHub profile is retrieved. `jsonwebtoken` is then used to generate a JWT containing the user's ID and username, signed using a secret and stored in the backend's `env.`.

When authentication is triggered for a user, the Express middleware will read this JWT signed cookie using the secret. If valid and matching, then the user is identified. Otherwise, a `401 Unauthorized` response will be returned.
